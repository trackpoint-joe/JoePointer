AI Delivery Readiness Review

Before anyone trusts an AI result enough to act on it, the result should clear five checks. This page walks you through them and tells you whether to accept it or send it back.

An AI result is anything a model produces that someone will act on, such as a forecast, a risk score, a recommended action, or an answer from an AI assistant.

  1. 1Think of one AI result your team is being asked to trust.
  2. 2Mark each of the five gates Pass, Gap, or Unknown.
  3. 3Get a verdict and the questions to send back to the team.
Accept
Every check has evidence behind it.
Accept with conditions
It can be acted on once one or two missing answers come back.
Send back
Do not act on it yet. The questions go back to the team.

Accept is the reviewer's recommendation. The owner of the result still decides.

About two minutes. Nothing you mark leaves this page.

Built by Joe Pointer in September 2026. These are the questions I ask before I trust an AI result.

The Five Gates

Mark each gate based on what you actually know about the result. The verdict updates as you go, in the bar at the bottom of your screen and in the full panel below the gates.

Each gate also shows where the check happens. Some run automatically in the pipeline on every change. Some are a human review. Some are watched after launch.

Audience, objectives, problem

Who is this result for, what should change for them, and what stands in the way?
Human review
1
Audience
  • Who uses this result, and in what role?
  • What do they do today instead?
2
Objectives
  • What outcome should change for them, and who is accountable for it today?
  • What quantity would move if this works?
3
Problem
  • What breaks today that this result is meant to fix?
  • What decision does this result change?
  • Would a report, a list, or a spreadsheet get the same decision made?
Status for Gate 1, Audience, objectives, problem
2

Success criteria and baseline

How will you know it is better than the way the work gets done today?
Human review
  • What does success look like, in a number anyone can check?
  • What is the baseline, the simple rule or the current process, that this has to beat?
  • Has anyone actually run that baseline, or is it assumed?
  • What does a false alarm cost compared with a missed problem?
  • Was the threshold chosen with that in mind?
  • Over what population and what period?
Status for Gate 2, Success criteria and baseline
3

Evaluation

Was it tested on data it had never seen, the way it will be used for real?
Human review
  • Was the test data kept separate in time from the data the model learned on?In plain terms: was it graded on a stretch of time it had already learned from?
  • Could any input leak the answer the model is supposed to produce?In plain terms: is there a clue hidden in the data that gives away the answer?
  • Is the test set representative of what the model will see once it is live?In plain terms: does the practice test look like the real thing it will face later?
  • Is the score a calibrated probability, or only a ranking?In plain terms: when it says seventy percent, do about seventy out of a hundred of those turn out that way?
  • Were related records (the same site, the same equipment, the same customer) kept on one side of the split?In plain terms: if ten readings came from one machine, did all ten stay together on one side, training or test, instead of leaking across both?
  • What counts as a failure, and who defined it?In plain terms: someone decided what counts as wrong here. Who made that call, and would you agree with it?
Status for Gate 3, Evaluation
4

Claims check

Can every number reported about this result be traced to its source?
Automated check where possibleHuman review
  • Does every reported result trace to a named person, a shipped feature, or a linked measurement?
  • Could someone ask "show me" and get an answer in under a minute?
  • Is there a claim here that nobody currently on the team can stand behind?
  • Has anyone checked the number independently, beyond naming where it came from?
Status for Gate 4, Claims check
5

Adoption and value

Are people actually using this result, and which person owns it after launch?
Monitored after launchHuman review
  • Is this actually used in the work, or only available to use?
  • How is the benefit measured, and who checks it?
  • Who owns this after the team that built it moves on?
  • Do the people using the output trust it, and can they tell you when it is wrong?
  • What is watched after launch, and what triggers a rollback?
  • Is the benefit measured in the same quantity named in Gate 1?
Status for Gate 5, Adoption and value
Send back
Gate 1 (audience, objectives, problem) and Gate 3 (evaluation) have not passed. Neither can be traded away, so this goes back to the team.
How the verdict works. Any gate not marked Pass counts against the result. Gate 1 and Gate 3 cannot be traded away, so if either has not passed, the result goes back to the team. A claim marked Gap in Gate 4 sends it back too. Otherwise, all five passed is accept, one or two not passed is accept with conditions, and three or more is send back.

Applied To My Own Work

Quality Control on AI Output in Production

The AI I was using on Future Me, Answered invented two testimonials, and they stayed live for three months before a review agent I built caught them. What changed afterward was where the rule lives and where the review runs.

My rule against invented quotes lived in a comment in one code file. Until that sweep, the review agent had never been pointed at the marketing pages, and it was not on the pull request path.

  • Gate 1Not the failure pointIt was already clear who the page was for and what it had to do.
  • Gate 2Not the failure pointNo baseline question was in play here.
  • Gate 3Not applicable, no model hereNothing was trained, so there was no evaluation to test. The veto applies to model-backed results.
  • Gate 4Gap, twiceThe rule lived in a code comment in one file, and the review agent was never pointed at the marketing pages or put on the pull request path.
  • Gate 5Not the failure pointAdoption was not what failed here.

The fix. I moved the rule into the instruction file every AI session loads now: every public claim has to trace to a named person, a shipped feature, or a linked measurement. My co-founder and I put review agents on every pull request, not only where I happened to aim it.

The recurrence. Three weeks later, the same kind of defect came back. This time it was caught on the first commit, before it ever reached a live page.

Where I Missed It Gate 2 miss

In April I built a demo dashboard for an electric cooperative, including a price forecast on simulated data. I skipped the baseline. This review would have caught it.
